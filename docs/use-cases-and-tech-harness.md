# Abilities, use cases and the tech harness

Each row is an **ability**: what the system does, in general terms, and the steps it always runs. Under it are the **examples** built in the demo. The capability codes (D1, O3…) are defined in the harness at the bottom, so every ability traces to what has to be built.

One use case can use several abilities. "Launch the Winter Hearth collection" is ability 1 (create the content) plus ability 15 (keep "never claim non-toxic" as a rule) plus ability 18 (launch the media campaign from the new copy).

### The pieces that make it agentic

1. **Durable workflow runtime (O1, O2).** Claire's week is one task that lives Monday to Friday, crosses email, Slack and the product, and acts on its own at a deadline.
2. **One review policy engine (O3).** Every agent asks the same question before acting: tell, draft or do. Widening autopilot changes behavior everywhere at once.
3. **One semantic layer (D4), with retailer as a dimension (P3).** The email, every page and the deck show the same number, for one retailer or all of them.
4. **Shared state between agents (M5).** Content and media don't message each other; both read and write one keyword ledger. Adding an agent means reading the ledger, not wiring a new pair.
5. **Actionable channels with identity (N1, N2).** A YES in an email is signed, tied to the person, and does what the product button does.
6. **Memory with evals (M1–M4).** Corrections, knowledge and skills are stored once, applied everywhere, and gated by tests.
